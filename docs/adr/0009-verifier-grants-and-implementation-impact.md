# ADR-0009 · 검증자 권한 추가와 구현 변경의 영향을 구분

- 날짜: 2026-11-21
- 상태: 개인 Sova 코드에 채택. 운영 DB 적용·새 방향별 자격 발행과는 별도.
- 관련: [검증 probe 원칙](0007-probe-design-principles.md), [운영 자격](0008-migration-production-qualification.md).

## 문제

검증자의 `allowed_scopes`는 이전 단위의 resource ID에 결속된다. 이 ID는 snapshot의 지문을 포함한다. 기존 trust outbox는 키 등록을 포함한 모든 변경을 `verifier` 구현 변경으로 보냈다.

따라서 다음 순환이 생겼다.

```text
snapshot → unit ID → 해당 unit의 검증 키 권한 등록
    → 구현 변경으로 오분류 → snapshot 갱신 요구
    → 다른 unit ID → 다시 권한 등록 필요
```

이는 단순히 시험 준비 순서를 바꾸는 것으로 해결되지 않는다. 게이트의 실제 검증자 구현 변경 차단은 타당하지만, 권한 추가를 구현 교체로 잘못 분류한 것이 문제다.

## 결정

기존 `policy`와 `verifier` 의미를 재사용한다. 새로운 실행 권한이나 게이트 우회 값은 만들지 않는다.

| trust 이력 | 이벤트 | 기존 증거 | 계획 |
| --- | --- | --- | --- |
| 알려진 형식·동일 tenant/app/key에 결속된 미회수 신규 키 등록 | `policy`, 환경·대상 미지정 | 변경 시각 이전·동시 증거 전부 무효 | 입력·다른 조건이 같으면 구조 유지 |
| 동일 키·검증 버전·유효기간 등 다른 모든 trust 항목을 유지한 scope 추가 | `policy` | 동일하게 재검증 필수 | 동일 |
| scope 축소·교체, 회수, 검증 버전 변경, 유효기간 변경 | `verifier` | 현재 신뢰·회수 여부도 계속 재조회 | 기존 보수적 실행 차단 유지 |
| 문서 버전·행 결속·scope가 불일치해 권한 추가로 분류할 수 없음 | `verifier` 또는 DB 발행 거부 | 정상으로 간주하지 않음 | 차단 |
| 실제 검증자 구현 변경 수집 | 기존 `verifier` | 재검증 필요 | 계속 차단 |

정책 변경에서 `commands_allowed=true`가 될 수 있다는 것은 모든 gate가 통과했다는 뜻이 아니다. 각 단계가 요구하는 증거, 승인, lease, 원격 효과·후속 검증이 계속 필요하다. 이전 증거의 서명이 유효하더라도 변경 시각 이전의 PASS를 재사용하지 않는다. 수집 완전성이 UNKNOWN이면 실행을 허용하지 않는다.

신규 분류는 승인 절차를 대신하지 않는다. 기존 독립 승인·불변 trust 저장·현재 키 조회를 사용한다. DB 런타임은 신뢰할 제어면에만 제공하며 앱·AI·업로드 산출물에 제공하지 않는다.

## 저장과 업그레이드

29번째 owner migration `postgres_verifier_grant_impact_v1.sql`로 outbox trigger의 향후 발행만 변경한다. 과거 migration의 텍스트·체크섬과 이미 기록한 이벤트는 수정하지 않는다. 새 테이블, runtime 쓰기 권한 확대, watermark 발행은 없다.

기존 이벤트로 차단된 계획은 새 분류로 소급 정상화하지 않는다. 새 관측·계획·승인·검증을 거친다. 운영 반영 시 migration owner로 schema를 적용하고, 일치하는 코드·실행 프로필을 배포해 readiness를 확인해야 한다. runtime 역할이 migration을 실행하거나 함수를 교체할 수 없어야 한다.

## 시험 경계

실제 PostgreSQL에서 신규 grant, 순수 scope 추가, 기존 PASS 무효화·새 검증, 회수·scope 축소·유효기간·버전 변경 차단, 잘못된 행의 차단, 이전 이력 보존·업그레이드 멱등성·runtime migration 거부를 확인한다. 기존 HTTP 업무·원장·실행기·복귀 회귀와 함께 실행한다.

로컬 흐름 시험의 위치 선언은 명시적 fixture다. 범주별 사실을 따로 두고 위치 관측자가 없으면 실제 실행 경로가 계속 실패하도록 한다. DB 주석 하나를 백업·감사·AI 데이터의 위치 증거로 재사용하지 않는다. 시험용 선언은 지정된 일회용 control DB에서만 사용할 수 있으며 운영 위치 자격으로 합산하지 않는다.
