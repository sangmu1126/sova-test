# 통합 명세 추적표 (워크로드 대응 실행기)

기준: 「계약·능력 기반 전방향 운영 인계 플랫폼 — 통합 상세 설계 명세」 MIG-SPEC-001 통합 1.1-draft(2026-11-11). 대상은 이 레포의 [워크로드 대응 실제 실행기](workload-response-runtime.md)다. `src/sova`의 제어면 구현 현황은 [구현 현황](implementation-status.md)에서 따로 관리한다.

이 외부 통합 초안의 전문·고정 원문 링크는 이 저장소에 포함돼 있지 않다. 아래 ID·절 번호를 저장소 자체의 [목표 명세 v2](sova-production-spec-v2.md)와 동일한 번호 체계로 읽지 않는다. 원문 전체의 요구사항 누락 여부와 두 문서의 우선순위까지 이 표만으로 확정할 수는 없다.

명세 V.4에 따라 상태를 아래처럼 나눈다. 한 경로에서 통과한 시험을 다른 클라우드, 서비스, DB로 일반화하지 않는다.

| 표기 | 뜻 |
|---|---|
| 실환경 | 실행 전용 EKS 출발지 → 이 Mac RKE2 목적지에서 실제로 실행해 통과 |
| 로컬 | 이 Mac의 RKE2 한 대(두 namespace)에서 실행해 통과 |
| 단위 | 결정적 단위 시험으로 고정. 클러스터 실행 없음 |
| 구현 | 코드는 있으나 해당 실패를 주입한 시험은 없음 |
| 없음 | 구현하지 않음 |
| 범위 밖 | 이 실행기의 목표가 아님 |

## Part I 불변조건

| ID | 상태 | 근거 |
|---|---|---|
| INV-01 단일 업무 권한 | 실환경 | 데이터 전환 중 두 DB의 앱 로그인 차단(`both_app_logins_fenced`), 활성화 뒤 목적지만 writer, 독립 시험의 단일 writer 재확인 |
| INV-03 재시도 멱등 | 단위 | 효과 원장: 같은 `request_id`와 같은 입력 해시는 기존 결과 반환, 다른 입력은 `idempotency_conflict` |
| INV-04 효과 불명 시 추측 진행 금지 | 실환경 | 확인하지 못한 효과는 `held`로 멈추고 자동 재실행하지 않음. 오늘 실제 보류 3건의 원인을 찾아 고친 기록이 커밋에 있음 |
| INV-05 승인과 계획 일치 | 실환경 | 계획에 클러스터·namespace·Pod UID와 만료를 결속. 승인 시 현재 Pod UID가 다르면 `workload_changed_replan_required` |
| INV-06 미확인·만료·서명 불일치는 PASS 아님 | 실환경·단위 | 서명 증거 완료 게이트(`signed_evidence_rejected`). 위조, 재사용, 만료, 드리프트, FAIL 거부는 단위 시험 |
| INV-08 코드 변경 시 재평가 | 단위 | 증거에 실행 중 코드 digest를 결속. 다른 코드의 증거는 완료에 쓰지 못함 |
| INV-09 AI 운영 권한 없음 | 범위 밖 | 실행기에 AI 경로 없음 |
| INV-10 원본 폐기 별도 승인 | 구현 | 원본 namespace, DB, PV를 자동으로 지우지 않음. 폐기 기능 없음 |
| INV-11 조직 경계 | 단위 | 소유자 라벨과 namespace UID를 매 호출 확인. 다른 소유자의 namespace, 범위 밖 namespace, 소유자 라벨 없는 문서는 변경 전에 거부(단위 시험). 단일 조직이라 다중 테넌트 실시험은 없음 |
| INV-12 복제용 쓰기와 업무 쓰기 분리 | 실환경 | 복사는 제어 probe의 관리 역할, 업무 쓰기는 앱 역할과 쓰기 게이트 |

## Part I 기능과 프로토콜

| 항목 | 상태 | 근거·한계 |
|---|---|---|
| §1.2 PLANNED_SINGLE_AUTHORITY | 실환경 | 정지·복사(2,000행 상한) 후 단일 writer 인계 |
| §1.2 PARTITIONED_HANDOFF, REVERSE_MIGRATION, FAILBACK | 없음 | 지원 선언이 역방향·failback을 `UNSUPPORTED`로 표시 |
| §11 방향별 자격, §28.4 자격 기록 | 실환경 | `support-record-*.json`. 프로필, 방향, 코드, 유형별 서명 증거, 한계, 제외, 만료 |
| §15 활성화 의도 | 구현·단위 | `migration_authority`가 `source → target_pending → target`. `target_pending`이면 초기화가 원본을 자동으로 다시 열지 않음(AT-20 장애 주입 시험) |
| §15.5 실효 fence | 실환경 | 출발지 앱 역할 `NOLOGIN`과 기존 앱 세션 종료. 데이터 전환과 자격 회전에서 확인 |
| §15.6 재기동 격리 | 실환경 | 독립 시험에서 새 목적지 인스턴스가 쓰기를 닫은 채 시작하고, 단일 writer 확인 뒤에만 엶 |
| §16 데이터 비교 | 실환경 | messages·jobs 전체 내용 지문 비교. CDC, 대용량, 객체 저장소는 없음 |
| §18 경로 전환 | 실환경 | 진입점(edge) 경로 전환. 오래된 경로는 출발지 fence가 거부 |
| §19 취소·복귀 | 구현 | 초기화가 목적지 신규 데이터를 출발지로 되돌림. failback 자격은 아님 |
| §20 출발지 독립 | 실환경 | `exit drill`: 출발지 경로를 거둔 채 새 인스턴스, 단일 writer, 쓰기와 읽기 |
| §22 보안 통제 | 실환경(일부) | 역할별 허용 NetworkPolicy, 노드 /32 터널 허용, Secret 값 비노출, kubectl stderr 비공개 |
| §23 증거 계약 | 실환경 | Ed25519 봉투, 계획·환경·코드·유효기간 결속, Object Lock 보존(§23.4). 독립 검증기 신원은 없음 |

## Part I 수락 시험(해당 항목)

| AT | 상태 | 근거 |
|---|---|---|
| AT-02 역할 교환 | 단위 | 역방향 선언은 `UNSUPPORTED` |
| AT-03 미지원 목적지 | 단위 | 기록 없음 또는 프로필 변경 시 `NEEDS_EVIDENCE`와 이유 |
| AT-08/09 같은 key 재시도, 다른 payload | 단위 | 효과 원장의 멱등과 충돌 |
| AT-21 활성화 후 조정기 중단 | 단위 | 시작 상태로 남은 효과는 재시작 때 `unknown`과 `held`가 되고 자동 재실행하지 않음 |
| AT-22 순서 역전·중복 명령 | 단위 | 오래된 revision 명령은 `stale_or_busy_command`, 같은 요청 재전송은 한 번만 실행 |
| AT-11 대상 UID 변경 | 실환경·단위 | 승인 시 Pod UID를 다시 확인해, 같은 이름에 새 UID면 `workload_changed_replan_required`(단위 시험). 증거의 환경 digest 드리프트도 거부 |
| AT-12 증거 만료·재생·다른 run | 단위 | 서명 증거 시험 |
| AT-17 fence 이후 기존 세션 | 실환경 | 자격 회전에서 회전 전 세션이 서버 쪽에서 끊긴 것을 확인 |
| AT-19 source 차단 확인 불가 | 단위 | 출발지 이전 자격 로그인이 되면 목적지 활성화 전에 `source_writer_not_fenced`로 멈추고 목적지 로그인을 열지 않음(장애 주입 시험) |
| AT-20 활성화 응답 유실 | 단위 | `target_pending`에서 writer 상태가 모호하면(둘 다 닫힘, 둘 다 열림, 원본만 열림) 초기화가 `writer_authority_ambiguous`로 보류하고 원본을 다시 열지 않음(장애 주입 시험) |
| AT-32 과거 writer 자동 재활성화 | 실환경(재기동 범위) | 재기동 인스턴스 쓰기 보류. 스냅샷 복원은 없음 |
| AT-34 중앙 플랫폼 중단 | 일부 | 실행기와 화면 서버는 업무 경로에 없다. 다만 이 시험 배치에서는 진입점이 출발지로 향하는 동안 업무 경로가 이 Mac의 SSM 터널 프로세스를 지난다. 그래서 제어 호스트가 멈추면 출발지 진입도 멈춘다. 이전 뒤 목적지 경로는 터널과 무관하다(`exit drill`). 운영에서는 진입점을 클라우드 LB나 DNS에 둔다 |
| AT-35 출발지 차단 후 새 기동 | 실환경 | `exit drill` |
| AT-37 백업·감사 삭제 거부 | 실환경 | Object Lock(GOVERNANCE) 버킷에 증거 411개 보존. 쓰기 역할의 잠긴 버전 삭제와 보존 단축은 AccessDenied, 원본은 SHA-256 일치(`demo/audit_shipper`). WORM이 키 삭제나 로그 누락까지 막지는 않음 |
