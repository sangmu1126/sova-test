# DB 준비 순서 개발 기록

2026-11-19 · 시작 커밋 `7fc9f509d8aab729d2db285de30dc2534f9610f1`.

## 범위와 진단

다른 개인 작업 트리는 `e51b6a2` 기준으로 `tests/integration/test_kafka_compacted.py`만 수정 중이었다. 이번 fixture·준비 순서 경로와 겹치지 않았다. 이는 로컬 파일 관측이며 다른 세션의 승인 응답은 아니다.

이전 `authority-read-concurrency-20261119/accepted-cold`는 source DB 버전 조회의 `ConnectionTimeout`으로 실패했다. 실제 업무 부하·Pod 승인·이전 실행 전에 중단된 경우다. 당시 기록과 실패는 유지한다.

재시도 추가나 연결 시간 상향 대신, 실행별 서버의 버전 관측을 클러스터 생성보다 앞으로 옮겼다. DB 이름과 TLS 상태도 실제 SQL로 읽어 관측 기록을 남긴다. 서비스 fixture는 동일 DB 쌍의 관측값만 받는다. 기본 호출자는 계속 직접 조회하므로 기존 서비스 시험의 동작도 유지한다.

제품 소스·이미지·adapter·schema·worker·승인·fencing·도메인·시간 한도는 바꾸지 않았다. `ad21e77`이 이번 준비 순서·기록·회귀 시험 커밋이다. Runner는 초기 실패 때도 호출한 `http_mode`를 남기도록 보완했다.

## 구성 요소 검증

`--suite bootstrap`으로 실제 TLS PostgreSQL에서 **7건 통과**, 실패·오류·건너뜀 0을 확인했다. 실제 버전 관측 뒤 이후 연결을 고장 주입해도 우회하지 않으며, 최초 조회 실패는 한 번만 시도하고 중단한다. 다른 DB의 기록도 거부한다. 기존 서비스 HTTP·DB 흐름을 같은 suite에서 검증했다. 시계 감시 통과와 전용 DB·네트워크 정리도 확인했다.

이 시험의 고장 주입은 특정 과거 장애의 원인을 재현한 것과 다르다. 버전 관측의 순서 분리와 오류 경계를 검증한 것이며, 과거 시간 초과의 기저 원인을 확정하지 않는다.

## 실제 실행

하네스 `ad21e7747fe2d48f8f9694f994ae8e8f1c7b276b`, 제품 소스 `0abcadcb4b8ab9426c747dbee39305c90d8916c7`, 고정 이미지 `sha256:bf94bd18080210a11900913116adf4de144e84a538fbbc25d9b101640574633a`, security `27e6e85514a7cbb3e43d216464b72d9bd78f3fcf`를 사용했다. src/ 제품 변경이 없으므로 새 이미지를 만들거나 다른 버전으로 대체하지 않았다. 세 실행은 모두 새 UUID 클러스터·DB·네트워크다.

- `cold`: 최초 실패 20/100(503 12·통신 8), 최종 SQL 103/103, 최대 부하 주문 완료 21,331.030ms.
- `prepared`: 최초 실패 18/100(503 14·통신 4), 최종 SQL 103/103, 최대 완료 22,567.860ms.
- `bounded`: 최초 실패 1/100(503 1), 호출 내 CONFIRMED 99·EXHAUSTED 1. 소진 사유는 8회 횟수 한도이며 최대 호출 시간은 2,511.294ms다. 부하 후 별도 조회·재전송 뒤 최종 SQL 103/103, 전체 완료 최대 23,176.935ms. 완료 한도 전체 충족으로 기록하지 않는다.

각 실행에서 HANDOFF_COMPLETE, 원래 주문 50건, 경로 PATCH 1회, 실제 SA/Pod/image 결속, 살아 있는 owner의 복구 거부, 실제 권한 거부 403, 잘못된 CA/호스트명 거부를 확인했다. 실제 설치 바이트 Sova 318·security 122개가 고정 제품 소스와 일치했다. 세 실행의 ClockWatch가 통과했다.

예전 실패를 삭제하지 않았으며 시간 초과가 다시 발생하지 않는다고 단정하지 않는다. 이번에는 그때 실패한 버전 발견을 실제 클러스터 기동 전에 끝내고 전달했으며 새 실행이 통과한 것이다. 단일 closed-loop 사례의 오류 수로 통계적 개선율·운영 가용성·금융 보안 자격을 발급하지 않는다.

시험 전용 컨테이너·네트워크 이름 14개를 읽기 전용으로 확인했고 모두 정리됐다. 재현용 캐시 이미지는 보존했다. 다른 세션은 `e8c6652`로 이동했으나 Kafka 시험·자체 개발 기록 경로만 변경됐고 이번 범위와 겹치지 않았다. 그 작업 트리는 변경하지 않았다.
