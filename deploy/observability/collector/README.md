# Standard OpenTelemetry Collector candidate

This is a minimal distribution of upstream OTel components, generated by official OCB 0.165.0. No custom receiver/exporter is implemented. It is not yet deployed to the personal source/target or qualified as a complete monitoring service.

## Reproduction

Use the verified Go 1.27.4 toolchain and OCB 0.165.0. Run `builder --config builder-config.yaml --skip-compilation`, then replace the generated `_build/go.mod` and `_build/go.sum` with these checked-in lock files. Build inside `_build` with `GOTOOLCHAIN=local CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -mod=readonly -trimpath -ldflags="-s -w" -o ../otelcol .`. The lock selects `golang.org/x/crypto v0.58.1-0.20261009181718-2f1f834330b2`; verify sums with the public Go checksum database.

Before packaging, `go list -deps ./...` must contain no `golang.org/x/crypto/openpgp` package. Build the scratch Dockerfile with `--platform linux/arm64 --network=none --pull=false`. Re-scan the exact image with a current vulnerability database, all severities, and no suppression file. Run the opt-in real Collector protocol test with the resulting immutable image ID. A matching version string alone does not qualify a binary.

## Actual result and limits

[Evidence](../../../docs/evidence/personal-otel-candidate-20261120.json) binds the built Linux/Darwin binaries, Linux image, current Trivy database and actual protocol test. The image had zero findings. The protocol test exercised actual mTLS, producer tokens, refusal, trusted scope replacement and sensitive-field removal with synthetic telemetry. It does not establish actual app instrumentation, backend retention, alert delivery or HA. Previous full-distribution candidates remain blocked; no ignore list or VEX exception was introduced.

Sources: [official OCB](https://opentelemetry.io/docs/collector/extend/ocb/), [upstream 0.165.0 manifest](https://github.com/open-telemetry/opentelemetry-collector-releases/blob/v0.165.0/distributions/otelcol-contrib/manifest.yaml), [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932). The OpenPGP advisory also states that unmaintained OpenPGP is unsafe; a module upgrade alone must not be represented as fixing an included OpenPGP implementation.
